# Agent

An agent is the core unit of behavior in Better Agent. It brings together a model, instructions, tools, and runtime behavior into one typed definition. At minimum, an agent needs a `name` and a `model`.

```ts
import { defineAgent } from "@better-agent/core";
import { openai } from "./openai";

export const helloAgent = defineAgent({
  name: "hello",
  model: openai.model("gpt-4o"),
  description: "Greets users and answers general questions.",
});
```

## Instructions and Context

Use `instruction` for the agent's system behavior. It can be a static string or a function driven by validated context.

```ts
const writer = defineAgent({
  name: "writer",
  model: openai.model("gpt-4o"),
  instruction: "You are a concise technical writer.",
});
```

Use `contextSchema` to define typed, validated runtime data for a run — like the current user, plan, or workspace. The instruction function receives that validated context on every run.

```ts
import { z } from "zod";

const supportAgent = defineAgent({
  name: "support",
  model: openai.model("gpt-4o"),
  contextSchema: z.object({
    userId: z.string(),
    plan: z.enum(["free", "pro"]),
  }),
  instruction: (context) =>
    `Help user ${context.userId}. They are on the ${context.plan} plan.`,
});
```

## Tools

Tools let the agent act. Pass a single tool or an array. When a tool fails, the default behavior sends the error back to the model so it can recover. Use `toolErrorMode: "throw"` when you want a failure to stop the run immediately.

```ts
import { weatherTool, stockTool } from "./tools";

const assistant = defineAgent({
  name: "assistant",
  model: openai.model("gpt-4o"),
  tools: [weatherTool, stockTool],
});
```

See [Tools](/docs/concepts/tools) for defining tool contracts, server tools, client tools, and approval flows.

## Steps

Each step produces one model response. If that response includes tool calls, the results feed into the next step. The loop continues until the model finishes naturally, a stop condition is met, or the step limit is reached.

Use `maxSteps` to cap how many steps a run can take, and `stopWhen` when the run should stop based on your own workflow logic:

```ts
const researcher = defineAgent({
  name: "researcher",
  model: openai.model("gpt-4o"),
  tools: [searchWeb, readPage],
  maxSteps: 5,
  stopWhen: ({ stepIndex, context }) =>
    context.plan === "free" && stepIndex >= 1,
});
```

## Lifecycle Hooks

Use `onStep` and `onStepFinish` to observe or react to the agent loop at runtime. These run on the server and receive the current step context.

```ts
const loggingAgent = defineAgent({
  name: "logging",
  model: openai.model("gpt-4o"),
  onStepFinish: ({ stepIndex, response }) => {
    console.log(`Step ${stepIndex} finished:`, response.finishReason);
  },
});
```
