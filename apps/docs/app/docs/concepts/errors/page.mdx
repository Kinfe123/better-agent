# Errors

Better Agent uses `BetterAgentError` as the standard error type across the framework. It carries a stable `code` for programmatic handling so you can build reliable error recovery without string-matching error messages.

## Error shape

### Server

`BetterAgentError` extends `Error` and adds structured fields:

```ts
import { BetterAgentError } from "@better-agent/shared/errors";

try {
  const result = await app.run("assistant", { input: "Hello" });
} catch (error) {
  if (error instanceof BetterAgentError) {
    console.log(error.code);     // stable code like "VALIDATION_FAILED"
    console.log(error.message);  // human-readable message
    console.log(error.status);   // HTTP status code
    console.log(error.retryable); // whether retrying may help
    console.log(error.context);  // additional context
  }
}
```

| Field | Type | Description |
| --- | --- | --- |
| `code` | `string` | Stable error code, such as `"VALIDATION_FAILED"`. |
| `message` | `string` | Human-readable error message. |
| `status` | `number` | HTTP status code. |
| `title` | `string` | Short title, such as `"Unprocessable Entity"`. |
| `type` | `string` | Docs URL for the error code. |
| `retryable` | `boolean` | Whether retrying may help. |
| `context` | `Record<string, unknown>` | Additional context for the error. |

### Client

On the client side, errors are normalized into `AgentClientError` — the same fields plus a `raw` field holding the original thrown value:

```ts
import { toAgentClientError } from "@better-agent/client";

try {
  await client.run("assistant", { input: "Hello" });
} catch (error) {
  const clientError = toAgentClientError(error);
  console.log(clientError.code);
  console.log(clientError.message);
  console.log(clientError.retryable);
  console.log(clientError.raw); // original thrown value
}
```

The client parses error responses from the server automatically. JSON bodies with `code`, `detail`, `status`, `retryable`, `context`, `issues`, and `trace` fields are all preserved in the client error.

## Error recovery

Use `error.retryable` to decide whether to retry automatically. Transient errors like network timeouts are `retryable: true`. Input validation errors are `retryable: false`. For agent tool errors specifically, see `toolErrorMode` on the [Agent](/docs/concepts/agent) page.
