# Events

Events stream what happens during a run as it happens. Every event has a `type` and a `timestamp`. Most apps only handle a small subset, so don't feel obligated to handle every type.

## Consuming events via streaming

Use `stream.events` to iterate over events as they arrive:

```ts
const stream = await app.stream("assistant", {
  input: "What's the weather in Tokyo?",
});

for await (const event of stream.events) {
  switch (event.type) {
    case "TEXT_MESSAGE_CONTENT":
      process.stdout.write(event.delta);
      break;
    case "TOOL_CALL_RESULT":
      console.log("Tool result:", event.result);
      break;
    case "RUN_FINISHED":
      console.log("Done");
      break;
  }
}
```

The `stream` object also exposes `runId` and a `result` promise for the final run result.

## onEvent callback

Use `onEvent` on run options when you don't need the full stream handle:

```ts
await app.run("assistant", {
  input: "Summarize this document...",
  onEvent: (event) => {
    if (event.type === "STEP_FINISH") {
      console.log(`Step ${event.stepIndex + 1} done`);
    }
  },
});
```

## Run lifecycle events

These events mark the boundaries of a run:

| Event | Key fields | Description |
| --- | --- | --- |
| `RUN_STARTED` | `runId`, `agentName`, `conversationId`, `runInput` | Run began. |
| `RUN_FINISHED` | `runId`, `finishReason`, `output` | Run completed successfully. |
| the required value | `runId`, `error` | Run failed. |
| `STEP_FINISH` | `runId`, `stepIndex`, `terminationReason` | One model step completed. |

## Message and tool events

| Event | Description |
| --- | --- |
| `TEXT_MESSAGE_CONTENT` | A chunk of text from the model. Use `event.delta` to stream it. |
| the required value | The model finished generating text for this message. |
| `TOOL_CALL_START` | The model requested a tool call. |
| `TOOL_CALL_RESULT` | A tool call returned a result. |
| the required value | A human-in-the-loop approval is pending. |
| `TOOL_APPROVAL_UPDATED` | An approval was resolved or expired. |

## Stream resumption

When you configure a stream store in `persistence`, Better Agent appends every event to the store. A client that reconnects can call `resumeStream` with a sequence number to receive events it missed. See [Persistence](/docs/concepts/persistence) for store contracts.
