# Events

Events stream what happens during a run as it happens. Every event has a `type` and a `timestamp`. Most apps only handle a small subset — typically `TEXT_MESSAGE_CONTENT` for streaming text and `RUN_FINISHED` for completion.

## Consuming Events

### Streaming

Use `stream.events` to iterate over events as they arrive:

```ts
const stream = await app.stream("assistant", {
  input: "What's the weather in Tokyo?",
});

for await (const event of stream.events) {
  switch (event.type) {
    case "TEXT_MESSAGE_CONTENT":
      process.stdout.write(event.delta);
      break;
    case "TOOL_CALL_RESULT":
      console.log("Tool result:", event.result);
      break;
    case "RUN_FINISHED":
      console.log("Done");
      break;
  }
}
```

The `stream` object also exposes `runId` and a `result` promise for the final run result.

### onEvent callback

Use `onEvent` on run options when you don't need the full stream handle:

```ts
await app.run("assistant", {
  input: "Summarize this document...",
  onEvent: (event) => {
    if (event.type === "STEP_FINISH") {
      console.log(`Step ${event.stepIndex + 1} done`);
    }
  },
});
```

## Run Lifecycle Events

These events mark the boundaries of a run:

| Event | Description |
| --- | --- |
| `RUN_STARTED` | Run began. Carries `runId`, `agentName`, `conversationId`, and `runInput`. |
| `RUN_FINISHED` | Run completed. Carries the final result. |
| `STEP_FINISH` | One model step completed. Carries `stepIndex` and `terminationReason`. |
| `TEXT_MESSAGE_CONTENT` | A chunk of streaming text. Carries `delta`. |
| `TOOL_CALL_RESULT` | A tool finished executing. Carries the tool name and `result`. |
| `TOOL_APPROVAL_UPDATED` | A human-in-the-loop approval state changed. |
