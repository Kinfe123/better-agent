# Events

Events stream what happens during a run as it happens. Every event has a `type` and a `timestamp`. Most apps only handle a small subset — you pick the events you care about and ignore the rest.

## Consuming Events

Use `stream.events` to iterate over events as they arrive:

```ts
const stream = await app.stream("assistant", {
  input: "What's the weather in Tokyo?",
});

for await (const event of stream.events) {
  switch (event.type) {
    case "TEXT_MESSAGE_CONTENT":
      process.stdout.write(event.delta);
      break;
    case "TOOL_CALL_RESULT":
      console.log("Tool result:", event.result);
      break;
    case "RUN_FINISHED":
      console.log("Done");
      break;
  }
}
```

The `stream` object also exposes `runId` and a `result` promise for the final run result.

Use `onEvent` on run options when you don't need the full stream handle:

```ts
await app.run("assistant", {
  input: "Summarize this document...",
  onEvent: (event) => {
    if (event.type === "STEP_FINISH") {
      console.log(`Step ${event.stepIndex + 1} done`);
    }
  },
});
```

## Run Lifecycle Events

These events mark the boundaries of a run:

| Event | Description |
| --- | --- |
| `RUN_STARTED` | Run began. Includes `runId`, `agentName`, `conversationId`, and `runInput`. |
| `RUN_FINISHED` | Run completed. Includes `runId` and the finish reason. |
| `STEP_FINISH` | One model step completed. Includes `stepIndex` and `terminationReason`. |

## Message and Tool Events

These events carry the content of a run as it progresses:

| Event | Description |
| --- | --- |
| `TEXT_MESSAGE_CONTENT` | A text delta from the model. Includes `delta`. |
| `TOOL_CALL_START` | The model started a tool call. Includes `toolName` and `toolCallId`. |
| `TOOL_CALL_RESULT` | A tool call completed. Includes `result`. |
| `TOOL_APPROVAL_UPDATED` | A human-in-the-loop approval decision was made. Includes `state`. |

See [Human in the Loop](/docs/concepts/hil) for how approval events integrate with the run lifecycle.
