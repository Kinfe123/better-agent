# Human in the Loop

Human in the Loop pauses execution and waits for an approval decision before a tool runs. Use it when a tool is sensitive, costly, or irreversible — deleting data, issuing refunds, running infrastructure changes, or triggering UI actions that need user confirmation.

## Static approval

Set `approval` on the tool contract when the tool should always require approval:

```ts
import { defineTool } from "@better-agent/core";
import { z } from "zod";

const deleteDatabase = defineTool({
  name: "delete_database",
  schema: z.object({ databaseId: z.string() }),
  approval: {
    required: true,
    timeoutMs: 300_000,
    meta: { risk: "high" },
  },
}).server(async ({ databaseId }) => {
  await db.delete(databaseId);
  return { deleted: true };
});
```

When the agent calls `delete_database`, Better Agent pauses and emits a the required value event. Execution resumes only after an approval decision is submitted.

## Dynamic approval

Use `resolve` when approval should depend on runtime input or context:

```ts
const refundPayment = defineTool({
  name: "refund_payment",
  schema: z.object({ orderId: z.string(), amount: z.number() }),
  approval: {
    resolve: ({ input, context }) => ({
      required: input.amount > 100,
      timeoutMs: 60_000,
      meta: { amount: input.amount },
    }),
  },
}).server(async ({ orderId, amount }) => {
  await processRefund(orderId, amount);
  return { refunded: amount, orderId };
});
```

The resolver receives `context`, `input`, `runId`, `toolCallId`, `toolName`, and `toolTarget`. Its return value overrides `required`, `timeoutMs`, and `meta` for that specific call.

## Timeouts

Approval timeout is checked at three levels in order: the resolver return value, `approval.timeoutMs` on the tool contract, and `advanced.toolApprovalTimeoutMs` as the app-wide fallback. If approval times out, Better Agent emits a `TOOL_APPROVAL_UPDATED` event with `state: "expired"` and the run fails with a `TIMEOUT` error.
