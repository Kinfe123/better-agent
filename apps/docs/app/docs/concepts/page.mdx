# Concepts

This section covers the core building blocks of Better Agent. Read these pages to understand how the framework fits together before diving into integrations or plugins.

- [Agent](/docs/concepts/agent) — the fundamental unit of behavior, combining a model, instructions, tools, and context.
- [Tools](/docs/concepts/tools) — structured contracts that let agents call your code on the server, the client, or a hosted provider.
- [Providers](/docs/concepts/providers) — adapters that connect Better Agent to model APIs with declared, type-gated capabilities.
- [API](/docs/concepts/api) — how to expose your app over HTTP and call it programmatically.
- [Client](/docs/concepts/client) — the typed HTTP client for talking to a Better Agent server.
- [Events](/docs/concepts/events) — the structured event stream emitted during every run.
- [Persistence](/docs/concepts/persistence) — stores for durable conversation history and stream resumption.
- [Plugins](/docs/concepts/plugins) — cross-agent behavior like guards, lifecycle hooks, and custom endpoints.
- [TypeScript](/docs/concepts/typescript) — how type inference flows from server to client.
- [CLI](/docs/concepts/cli) — generate portable client types from your app definition.
- [Structured Output](/docs/concepts/structured-output) — define a schema for the model's response and get a typed result.
- [Human in the Loop](/docs/concepts/hil) — pause execution and wait for a human approval before a tool runs.
- [MCP](/docs/concepts/mcp) — connect agents to external tools and data over the Model Context Protocol.
- [Errors](/docs/concepts/errors) — stable error codes, shapes, and client-side normalization.
