# Persistence

Persistence stores conversation state across runs. Use it for durable conversations, stream resumption, and active-run tracking. You can adopt the stores you need, or skip persistence entirely for stateless flows.

```ts
import { betterAgent, createMemoryConversationStore, createMemoryStreamStore, createMemoryConversationRuntimeStateStore } from "@better-agent/core";

const app = betterAgent({
  agents: [assistantAgent],
  persistence: {
    conversations: createMemoryConversationStore(),
    stream: createMemoryStreamStore(),
    runtimeState: createMemoryConversationRuntimeStateStore(),
  },
});
```

The in-memory stores are useful for development. In production, implement the contracts on top of your existing database.

## Conversation Store

The conversation store loads and saves the durable `ConversationItem[]` array for a conversation.

```ts
interface ConversationStore {
  load(params: {
    conversationId: string;
    agentName: string;
  }): Promise<{ items: ConversationItem[]; cursor?: string | number } | null>;

  save(params: {
    conversationId: string;
    agentName: string;
    items: ConversationItem[];
    expectedCursor?: string | number;
  }): Promise<{ cursor: string | number }>;
}
```

When a run starts with a `conversationId`, `load()` fetches stored history, the agent loop runs and appends new messages, and on success `save()` is called with the full updated array. The `expectedCursor` field enables optimistic concurrency — if the cursor has changed since `load()`, the save is rejected.

## Stream Store

The stream store persists events emitted during a run so disconnected clients can resume where they left off.

```ts
interface StreamStore {
  open(streamId: string, meta: { runId: string }): Promise<void>;
  append(streamId: string, event: StreamEvent): Promise<void>;
  close(streamId: string): Promise<void>;
  resume(streamId: string, afterSeq?: number): AsyncIterable<StreamEvent>;
}
```

`resume()` yields events after a given sequence number — historical events first, then live events if the stream is still active.

## Runtime State Store

The runtime state store tracks which run is active for a conversation. It is used to detect and abort duplicate runs for the same `conversationId`.
