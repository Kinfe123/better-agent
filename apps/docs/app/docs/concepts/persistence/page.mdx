# Persistence

Persistence stores conversation state across runs. Use it for durable conversations, stream resumption, and active-run tracking. You can adopt the stores you need, or skip persistence entirely for stateless flows.

Better Agent provides three store contracts: a **Conversation Store** that loads and saves the conversation timeline, a **Stream Store** that persists emitted events for stream resumption, and a **Runtime State Store** that tracks which run is active for a conversation.

## Quick start with in-memory stores

Better Agent ships in-memory implementations of all three stores. These are suitable for local development or single-instance deployments.

```ts
import { betterAgent } from "@better-agent/core";
import {
  createMemoryConversationStore,
  createMemoryStreamStore,
  createMemoryConversationRuntimeStateStore,
} from "@better-agent/core";

const app = betterAgent({
  agents: [assistantAgent],
  persistence: {
    conversations: createMemoryConversationStore(),
    stream: createMemoryStreamStore(),
    runtimeState: createMemoryConversationRuntimeStateStore(),
  },
});
```

## Conversation store

Implement the conversation store contract to persist durable `ConversationItem[]` arrays in your own database:

```ts
interface ConversationStore {
  load(params: {
    conversationId: string;
    agentName: string;
  }): Promise<{ items: ConversationItem[]; cursor?: string | number } | null>;

  save(params: {
    conversationId: string;
    agentName: string;
    items: ConversationItem[];
    expectedCursor?: string | number;
  }): Promise<{ cursor: string | number }>;
}
```

When a run starts with a `conversationId`, Better Agent calls `load()` to fetch stored history, replays it into the model, runs the agent loop, and calls `save()` with the full updated array on success. The `expectedCursor` field lets you implement optimistic concurrency.

## Stream store

Implement the stream store to persist events so disconnected clients can resume where they left off:

```ts
interface StreamStore {
  open(streamId: string, meta: { runId: string }): Promise<void>;
  append(streamId: string, event: StreamEvent): Promise<void>;
  close(streamId: string): Promise<void>;
  resume(streamId: string, afterSeq?: number): AsyncIterable<StreamEvent>;
}
```

`resume()` yields historical events first, then live events if the stream is still active. This makes reconnection seamless for the client.

## Runtime state store

The runtime state store tracks which run is currently active for a conversation. It lets you abort in-flight runs and prevents concurrent runs on the same conversation from conflicting. The in-memory implementation is usually sufficient unless you run multiple server instances.
