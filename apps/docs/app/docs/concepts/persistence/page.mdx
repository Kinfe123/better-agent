# Persistence

Persistence stores conversation state across runs. Use it for durable conversations, stream resumption, and active-run tracking. You can adopt the stores you need, or skip persistence entirely for stateless flows.

Better Agent ships in-memory stores for local development:

```ts
import { betterAgent } from "@better-agent/core";
import {
  createMemoryConversationStore,
  createMemoryStreamStore,
  createMemoryConversationRuntimeStateStore,
} from "@better-agent/core";

const app = betterAgent({
  agents: [assistantAgent],
  persistence: {
    conversations: createMemoryConversationStore(),
    stream: createMemoryStreamStore(),
    runtimeState: createMemoryConversationRuntimeStateStore(),
  },
});
```

For production, implement the store contracts on top of your existing database.

## Store contracts

Better Agent defines three store contracts. Each is a small interface that maps cleanly to a table or collection.

### Conversation store

Loads and saves the durable `ConversationItem[]` array:

```ts
interface ConversationStore {
  load(params: {
    conversationId: string;
    agentName: string;
  }): Promise<{ items: ConversationItem[]; cursor?: string | number } | null>;

  save(params: {
    conversationId: string;
    agentName: string;
    items: ConversationItem[];
    expectedCursor?: string | number;
  }): Promise<{ cursor: string | number }>;
}
```

When a run starts with a `conversationId`, `load()` fetches stored history, the agent loop runs and appends new items, and `save()` is called on success with the full updated array.

### Stream store

Persists events emitted during a run so disconnected clients can resume:

```ts
interface StreamStore {
  open(streamId: string, meta: { runId: string }): Promise<void>;
  append(streamId: string, event: StreamEvent): Promise<void>;
  close(streamId: string): Promise<void>;
  resume(streamId: string, afterSeq?: number): AsyncIterable<StreamEvent>;
}
```

`resume()` yields historical events first, then live events if the stream is still active — so clients reconnecting mid-run see the full picture.

### Runtime state store

Tracks which run is currently active for a conversation. This lets you abort a previous run when a new message arrives in the same conversation:

```ts
interface ConversationRuntimeStateStore {
  get(conversationId: string): Promise<{ runId: string } | null>;
  set(conversationId: string, state: { runId: string }): Promise<void>;
  clear(conversationId: string): Promise<void>;
}
```

> **Note:** `expectedCursor` in the conversation store is optimistic concurrency. If your `save()` sees a different cursor than expected, throw to signal a conflict and prevent overwriting concurrent writes.
