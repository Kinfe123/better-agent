# Plugins

Plugins add behavior that applies across your entire app: logging, auth, rate limiting, lifecycle hooks, and custom endpoints. Register them once at the app level and they apply to every agent.

```ts
import { betterAgent } from "@better-agent/core";
import { rateLimitPlugin, loggingPlugin } from "@better-agent/plugins";

export const app = betterAgent({
  agents: [myAgent],
  plugins: [
    rateLimitPlugin({ windowMs: 60_000, max: 20 }),
    loggingPlugin({ level: "info" }),
  ],
});
```

## Creating a plugin

Use `definePlugin()` to create a custom plugin. Every plugin needs a unique `id`. A plugin can use any combination of guards, lifecycle hooks, event middleware, event observation, tools, and endpoints:

```ts
import { definePlugin } from "@better-agent/core";

export const myPlugin = definePlugin({
  id: "my-plugin",
});
```

## Guards

Guards run before a request is processed. Return `null` to allow, or a `Response` to reject:

```ts
const workspaceAuth = definePlugin({
  id: "workspace-auth",
  guards: [
    async ({ mode, agentName, request, input }) => {
      const token = request.headers.get("authorization");
      if (!token) {
        return new Response("Unauthorized", { status: 401 });
      }
      return null;
    },
  ],
});
```

The guard context includes `mode` (the request type), `agentName`, `input`, and the raw `Request` object.

## Lifecycle hooks

Plugins can hook into every phase of the agent loop. All hooks run in plugin registration order, before the agent's own hooks.

`onStep` runs before each step. Use it to mutate messages, set tool choice, filter active tools, or override the system instruction. `onStepFinish` runs after each step with access to the step result.

See the built-in plugins — [Auth](/docs/plugins/auth), Logging, Rate Limit, and IP Allowlist — for practical examples of what plugins can do.
