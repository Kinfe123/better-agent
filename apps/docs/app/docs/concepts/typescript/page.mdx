# TypeScript

Better Agent keeps your server and client in sync through TypeScript. Agent names, run context, structured output, and client tool handlers are all inferred from your app definition — no manual type declarations needed.

## What You Get

Each part of your app definition becomes a typed contract on the client:

| Definition | Client Type |
| --- | --- |
| `agent.name` | String literal union for the `agent` parameter |
| `agent.contextSchema` | Typed `context` field on `run()` and `stream()` input |
| `agent.outputSchema` | Typed `structured` field on the run result |
| Client tools (`.client()`) | Typed `toolHandlers` map with handler input inferred from the tool's schema |
| `model.caps` | Capability-gated fields — `modalities`, `outputSchema`, and similar only appear when the model supports them |

## Same Project

When your client and server share the same TypeScript project, import the app type directly.

```ts
// server.ts
export const app = betterAgent({ agents: [supportAgent] });
```

```ts
// client.ts
import { createClient } from "@better-agent/client";
import type { app } from "./server";

const client = createClient<typeof app>({
  baseURL: "/api",
  secret: "dev-secret",
});

// TypeScript knows "support" is a valid agent name,
// and that it requires userId and plan in context:
const result = await client.run("support", {
  input: "Help me reset my password",
  context: { userId: "user_123", plan: "pro" },
});
```

## Separate Packages

When your client and server live in different packages or repos, use the CLI to generate a portable `.d.ts` file.

```bash
npx @better-agent/cli generate type --config ./server.ts
```

The generated file exports a single type alias with no runtime values — safe to ship in any bundle. Import it the same way you'd import the app type directly:

```ts
import type { BAClientApp } from "./better-agent.types";

const client = createClient<BAClientApp>({
  baseURL: "https://api.example.com",
  secret: process.env.BETTER_AGENT_SECRET!,
});
```

See [CLI](/docs/concepts/cli) for the full list of generation options.
