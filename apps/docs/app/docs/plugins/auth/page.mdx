# Auth

The auth plugin blocks requests unless they provide a valid API key. Use static keys for simple setups, or provide your own validation logic for database-backed or agent-specific rules.

## Basic Usage

By default the plugin reads the key from the `x-api-key` header.

```ts
import { authPlugin } from "@better-agent/plugins";

const plugin = authPlugin({
  apiKeys: ["dev-key"],
});
```

Register it in your app:

```ts
const app = betterAgent({
  agents: [myAgent],
  plugins: [plugin],
});
```

## Custom Header

Use `header` when your key lives in a different header.

```ts
const plugin = authPlugin({
  header: "authorization",
  apiKeys: ["Bearer dev-key"],
});
```

## Custom Validation

Use `getKey` and `validate` when you need your own auth logic — keys from a database, another service, or agent-specific rules.

```ts
const plugin = authPlugin({
  getKey: ({ request }) => request.headers.get("authorization"),
  validate: ({ key, agentName }) => key === `${agentName}-key`,
});
```

If validation fails, the plugin returns `401 Unauthorized`. The request does not reach the agent.

> **Note:** The `secret` field on `betterAgent()` provides a simpler bearer-token guard for development. The auth plugin is for production use cases that need key lists or custom logic.
