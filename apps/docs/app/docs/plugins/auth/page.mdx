# Auth

The auth plugin blocks requests unless they provide a valid API key. Use static keys for simple setups, or provide your own validation logic for database-backed or agent-specific rules.

## Basic Usage

By default the plugin reads the key from the `x-api-key` header.

```ts
import { authPlugin } from "@better-agent/plugins";

const plugin = authPlugin({
  apiKeys: ["dev-key"],
});
```

## Custom Header

Use `header` when your key lives in a different header, such as `authorization`.

```ts
const plugin = authPlugin({
  header: "authorization",
  apiKeys: ["Bearer dev-key"],
});
```

## Custom Validation

Use `getKey` and `validate` when you need your own auth logic — for example, when keys come from your own database or need to vary per agent.

```ts
const plugin = authPlugin({
  getKey: ({ request }) => request.headers.get("authorization"),
  validate: ({ key, agentName }) => key === `${agentName}-key`,
});
```

If validation fails, the plugin returns `401 Unauthorized` and the request does not reach the agent.

## Register the Plugin

```ts
import { betterAgent } from "@better-agent/core";
import { authPlugin } from "@better-agent/plugins";

const app = betterAgent({
  agents: [myAgent],
  plugins: [
    authPlugin({ apiKeys: [process.env.BETTER_AGENT_API_KEY!] }),
  ],
});
```

> **Note:** The built-in `secret` field on `betterAgent()` provides bearer token auth at the HTTP handler level. The auth plugin is for more advanced scenarios — per-agent keys, custom headers, or database-backed validation.
