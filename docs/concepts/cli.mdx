# CLI

The Better Agent CLI generates a `.d.ts` file from your app's agent definitions. This gives your client full type safety — typed agent names, context schemas, and tool contracts — without importing any server code into the client bundle.

## Generate client types

Run the generator by pointing `--config` at the file that exports your `betterAgent()` app:

```bash title="Terminal"
npx @better-agent/cli generate type --config ./server.ts
```

Or with the global command:

```bash title="Terminal"
better-agent generate type --config ./server.ts
```

The command discovers exported `betterAgent()` instances in the config file, extracts agent and tool type information, and writes a portable type declaration to disk.

### Options

| Option | Default | Description |
| --- | --- | --- |
| `--config <path...>` | — | One or more config file paths. Required. |
| `--cwd <path>` | `process.cwd()` | Base directory for resolving relative paths. |
| `--out <path>` | `better-agent.types.d.ts` | Output path for the generated `.d.ts` file. |
| `--name <identifier>` | `BAClientApp` | Exported type alias name. |
| `--yes` | `false` | Skip prompts and overwrite the output file. |

### Full example

```bash title="Terminal"
npx @better-agent/cli generate type \
  --config ./server.ts \
  --out ./src/types/better-agent.d.ts \
  --name MyApp \
  --yes
```

## Use the generated types

Import the generated type and pass it to `createClient` for full inference. Agent names, context shapes, structured output, and client tool handlers all flow through that type parameter.

```ts title="client.ts"
import type { BAClientApp } from "./better-agent.types";
import { createClient } from "@better-agent/client";

const client = createClient<BAClientApp>({
  baseURL: "http://localhost:3000/api",
});

const result = await client.run("assistant", {
  input: "Hello!",
});
```

If your client and server are in the same project, you can import the server app type directly instead of using the generated file. The CLI approach is designed for cases where the two sides live in separate packages or repositories. See [TypeScript](/docs/concepts/typescript) for more on both patterns — but note that only routes in the navigation are linkable here; reach that page through the Core Concepts section.

## Polyrepo setup

When your client and server live in separate repositories, generate the types in the server repo and copy or publish the output file.

Generate in the server:

```bash title="Terminal"
npx @better-agent/cli generate type \
  --config ./better-agent.ts \
  --out ../client/src/types/server.d.ts
```

Import in the client:

```ts title="client.ts"
import type { BAClientApp } from "./types/server";
import { createClient } from "@better-agent/client";

const client = createClient<BAClientApp>({
  baseURL: "https://api.example.com",
});
```

## Config discovery

The CLI loads TypeScript or JavaScript files using the runtime bundler and searches for exported `betterAgent()` app instances. If a file exports multiple apps, the CLI lists them and prompts you to choose. Pass `--yes` to accept all without prompting.

## Troubleshooting

**Config doesn't load.** The CLI resolves imports relative to the config file. If your project uses path aliases such as `@/`, they may not resolve in the CLI's loader. Switch to relative imports in the config file:

```ts title="server.ts"
// works
import { tools } from "./tools";

// may not resolve
import { tools } from "@/tools";
```

**No app export found.** The config file must export the `betterAgent()` return value as a named or default export, not as an unexported variable:

```ts title="server.ts"
// correct — named export
export const app = betterAgent({ agents: [myAgent] });

// incorrect — not exported
const app = betterAgent({ agents: [myAgent] });
```
