# Persistence

Persistence stores conversation state across runs. Use it for durable conversations, stream resumption, and active-run tracking. You can adopt the stores you need, or skip persistence entirely for stateless flows.

Better Agent provides three store contracts. You implement them on top of your existing database.

```ts
import { betterAgent } from "@better-agent/core";
import {
  createMemoryConversationStore,
  createMemoryStreamStore,
  createMemoryConversationRuntimeStateStore,
} from "@better-agent/core";

const app = betterAgent({
  agents: [assistantAgent],
  persistence: {
    conversations: createMemoryConversationStore(),
    stream: createMemoryStreamStore(),
    runtimeState: createMemoryConversationRuntimeStateStore(),
  },
});
```

> **Note:** The in-memory stores are suitable for local development or single-instance deployments. Use a database-backed implementation for production.

## Conversation Store

The conversation store loads and saves durable `ConversationItem[]` arrays. Implement `load()` and `save()` against your existing database or ORM:

```ts
interface ConversationStore {
  load(params: {
    conversationId: string;
    agentName: string;
  }): Promise<{ items: ConversationItem[]; cursor?: string | number } | null>;

  save(params: {
    conversationId: string;
    agentName: string;
    items: ConversationItem[];
    expectedCursor?: string | number;
  }): Promise<{ cursor: string | number }>;
}
```

When a run starts with a `conversationId`, Better Agent calls `load()`, replays stored history into the model, runs the agent loop, then calls `save()` with the full updated array. The `expectedCursor` field enables optimistic concurrency control.

## Stream Store

The stream store persists emitted events so disconnected clients can resume where they left off:

```ts
interface StreamStore {
  open(streamId: string, meta: { runId: string }): Promise<void>;
  append(streamId: string, event: StreamEvent): Promise<void>;
  close(streamId: string): Promise<void>;
  resume(streamId: string, afterSeq?: number): AsyncIterable<StreamEvent>;
}
```

`resume()` yields historical events first, then live events if the stream is still active. This makes stream reconnection straightforward — pass the last sequence number the client received.

## Runtime State Store

The runtime state store tracks which run is currently active for a conversation. It has a minimal contract with `get()`, `set()`, and `delete()` methods. Use it to prevent duplicate runs and to implement abort-run semantics.
