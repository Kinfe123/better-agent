# Persistence

Persistence stores conversation state across runs. Use it for durable conversations, stream resumption, and active-run tracking. You can adopt only the stores you need, or skip persistence entirely for stateless flows.

Better Agent provides three store contracts:

- **Conversation Store** — loads and saves the conversation timeline.
- **Stream Store** — persists emitted events for stream resumption.
- **Runtime State Store** — tracks which run is active for a conversation.

These are minimal contracts. You implement them on top of your existing database and schema.

## In-memory stores

For local development, Better Agent ships built-in in-memory stores:

```ts
import { betterAgent } from "@better-agent/core";
import {
  createMemoryConversationStore,
  createMemoryStreamStore,
  createMemoryConversationRuntimeStateStore,
} from "@better-agent/core";

const app = betterAgent({
  agents: [assistantAgent],
  persistence: {
    conversations: createMemoryConversationStore(),
    stream: createMemoryStreamStore(),
    runtimeState: createMemoryConversationRuntimeStateStore(),
  },
});
```

> **Note:** In-memory stores do not survive process restarts. Use them for development and testing only.

## Conversation store

The conversation store loads and saves durable `ConversationItem[]` arrays. Implement it with a `load()` and `save()` method:

```ts
interface ConversationStore {
  load(params: {
    conversationId: string;
    agentName: string;
  }): Promise<{ items: ConversationItem[]; cursor?: string | number } | null>;

  save(params: {
    conversationId: string;
    agentName: string;
    items: ConversationItem[];
    expectedCursor?: string | number;
  }): Promise<{ cursor: string | number }>;
}
```

When a run starts with a `conversationId`, `load()` fetches stored history, history is replayed into the model, the agent loop runs and appends new messages, and `save()` is called with the full updated array. `expectedCursor` enables optimistic concurrency — if it doesn't match the stored cursor, the save is rejected.

## Stream store

The stream store persists events emitted during a run so disconnected clients can resume where they left off:

```ts
interface StreamStore {
  open(streamId: string, meta: { runId: string }): Promise<void>;
  append(streamId: string, event: StreamEvent): Promise<void>;
  close(streamId: string): Promise<void>;
  resume(streamId: string, afterSeq?: number): AsyncIterable<StreamEvent>;
}
```

`resume()` yields events after a given sequence number — historical events first, then live events if the stream is still active. This is the primitive that powers reconnect-safe streaming in client adapters.
